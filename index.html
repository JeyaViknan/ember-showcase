Project

EMBER

Edge Mesh for Building Egress Routing

Author Jeyaviknan S R
Executive Summary

EMBER is a decentralised life-safety routing system for fire evacuation. A mesh of ESP32 nodes fuses local hazard readings, shares compact hazard vectors, and computes egress routes from the edge.

Instead of pointing people along a static shortest path, EMBER costs each corridor in physiological dose and routes on predicted conditions at the time an occupant will arrive there.

Problem Static signage can point into a corridor that becomes untenable during the walk.
Solution Every node solves its own predictive route using the shared building hazard table.
Difference Cost is dose, not a tuned score; silence is treated as unknown, never safe.

Architecture

Three tiers with deliberately different guarantees.

Allowed to fail

Cloud / Supervisory

Fire Commander dashboard, MQTT over WiFi, telemetry, logging, diagnostics and lifecycle.

Must not fail

Life-Safety Plane

ESP-NOW peer-to-peer mesh carrying encrypted 48-byte hazard vectors. No AP, DHCP, broker or internet dependency.

Every zone

Edge Node

ESP32 with DHT22, MQ-2, IR flame, WS2812 strip and occupancy feed. Each node holds the full graph and solves its own route.

Key Innovations

What makes EMBER technically interesting.

01

Predictive Hazard Mapping

Segments are evaluated at predicted arrival time, not only at alarm time.

02

Decentralised Edge Mesh

No master node: each ESP32 fuses, shares and solves locally.

03

Physiological Dose Routing

Smoke, heat, gas and exposure time become the route objective.

04

Distributed Decision Making

Forward-from-self Dijkstra maps naturally to one node, one answer.

05

Fault Tolerance

Unknown zones receive a conservative penalty; corrupted frames are rejected.

06

Validation

Acceptance suite, native unit tests and seeded scenarios reproduce the evidence.
